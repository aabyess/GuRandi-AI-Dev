# 트러블슈팅

모두 실제로 있었던 일이고, 팀 메모리와 커밋 기록에 남아 있습니다.

## 게임 버그

### 유닛 강화와 스킬이 한 달 동안 꺼져 있었다
- **증상:** 강화를 해도, 스킬이 있어도 효과가 없었다(08-28 ~ 09-29).
- **원인:** 유닛 프리팹에는 소유자 정보(OwnedByPlayer)가 없고 생성 뒤에 붙는다. 그런데 생성 직후(Awake)에 그 값을 읽어 저장해 두어서, 늘 「주인 없음」으로 굳었다.
- **해결:** 소유자 정보를 쓰는 시점에 다시 읽도록 바꿨다. 「코드가 있다」가 아니라 「실제로 발동했다」를 탐침으로 확인하는 것을 규칙으로 정했다. → [메모리](ai-workflow/memory/spawn-order-awake-cache.md)

### 히든 스킬 5개 미발동, 조합식 4개 무한 반복
- **원인:** AI가 생성한 유니티 데이터 파일(YAML)에서 목록이 키와 한 줄에 붙었다(`키:  - 항목`). 유니티는 그 뒤 필드를 기본값으로 읽는다.
- **해결:** 생성 도구를 고치고, 같은 모양을 찾는 검사를 넣었다. → [메모리](ai-workflow/memory/yaml-inline-list-trap.md)

### 적이 원작보다 7.2배 느렸다
- **원인:** 맵을 원작 대비 4.167배로 키우면서 이동 속도만 같이 키우지 않았다.
- **해결:** 단위 환산 상수(WorldScale)를 한 곳에 두고, 수치 검산은 문서가 아니라 실제 에셋 값으로만 한다.

### 컴파일이 깨진 채로 push됐다
- **원인:** 컴파일 검사 출력의 마지막 줄은 늘 「done」인데, AI가 `tail -1`로 그 줄만 보고 통과로 판단했다.
- **해결:** 오류 줄을 검색해서 판정하게 바꾸고, 이 함정을 메모리에 남겼다. → [메모리](ai-workflow/memory/csc-check-tail-hides-errors.md)

## AI 협업 문제

### 사실이 아닌 「완료」 보고
- **증상:** 「맞췄습니다」, 「앞에서 봤습니다」, 「14칸」, 「23종이 죽어 있습니다」 — 4건 모두 틀렸다.
- **원인:** 도구가 출력에 붙인 이름표(라벨)를 결과 자체로 읽었다.
- **해결:** 보고는 실행 화면 캡처, 테스트 탐침, 원본 수치를 근거로만 한다. 근거 없는 보고는 PM 리뷰에서 돌려보낸다. → [메모리](ai-workflow/memory/tool-labels-are-not-evidence.md)

### 「전부 확인했다」가 일부였다
- **증상:** 213개 중 181개, 애니메이션 클립 3개 중 2개만 보고 「전부」라고 했다.
- **해결:** 목록은 손으로 적지 않고 데이터에서 뽑는다. 보고에 「몇 개 중 몇 개」를 함께 쓴다. → [메모리](ai-workflow/memory/is-that-really-everything.md)

### 조사 문서를 근거로 착각
- **증상:** 이전 세션이 쓴 조사 문서의 수치로 밸런스를 맞췄는데, 그 문서는 그 숫자를 계산한 적이 없었다.
- **해결:** 원작 수치는 원본 맵 파일을 직접 디코드한 값만 근거로 삼는다. 그 기준으로 240여 기를 다시 대조해 80여 기를 바로잡았다. → [메모리](ai-workflow/memory/docs-are-not-evidence.md)

### 생성 도구를 검증용으로 돌려 데이터를 덮어썼다
- **증상:** 확인만 하려고 돌린 스크립트가 실제 데이터에 결과를 써서, 다른 유닛 15기의 이미지가 옛 버전으로 바뀌었다.
- **해결:** git으로 즉시 되돌리고, 스크립트의 기본 입력 경로를 최신 폴더로 바꿨다. 「생성 도구는 데이터를 쓴다」를 팀 규칙에 넣었다. → [메모리](ai-workflow/memory/generators-are-destructive.md)

### 여러 세션의 동시 커밋
- **증상:** 한 세션의 커밋에 다른 세션이 스테이징한 파일이 섞여 들어갔다.
- **해결:** `git commit -- <경로>` 형태만 허용하고, UI 담당은 별도 git worktree에서 작업한 뒤 PM이 병합한다. → [메모리](ai-workflow/memory/git-commit-index-race.md)

### 긴 대화에서 결정을 잊었다
- **증상:** 컨텍스트가 압축되면 확정된 결정을 놓치거나 닫힌 질문을 다시 꺼냈다.
- **해결:** 결정은 그때그때 메모리 파일로, 진행 상태는 NEXT_SESSION.md로 남긴다. 대화가 길어지면 압축되기 전에 PM이 스스로 새 세션으로 교체한다. → [메모리](ai-workflow/memory/session-rotation-by-pm.md)
