**도구가 결과문에 쓴 말은 그 도구가 그렇게 했다는 증거가 아니다. 우리가 그렇게 짰다는 증거일 뿐이다.**

2026-09-24 하루에 넷:

| 도구가 찍은 말 | 실제 |
|---|---|
| 메뉴 「위습 모양을 맞췄습니다」 | `.mat`은 한 글자도 안 바뀌어 있었다 (`SetDirty`는 저장이 아니다) |
| 진열 「**앞에서 봄**, 1행이 맨 앞」 | **전부 뒷면.** 유닛도 카메라도 +Z를 봤다 |
| 보고문 「구멍 14칸」 | 칸 크기를 바꾸니 1160칸 중 **2칸(0.17%)** |
| 검사 「23종이 죽습니다」 | 가르니 진짜는 9종. 11종은 **검사가 항목보다 나중에 생긴 것** |

「앞에서 봄」이 특히 비쌌다 — **그 도구로 한 「정면 사진」 판정이 코드 주석과 문서에 남아
결론 하나를 닫아 두고 있었다**(히든_유닛A Hips). 사진도 결론도 둘 다 틀렸다(3ad037eb).
그리고 **같은 파일 안에서 `idleview`는 원래 맞았다.** 한 번 제대로 생각한 앎이 옆 함수로 안 건너갔다.

**How to apply:**
- 도구가 「됐다」고 하면 **결과물을 직접 연다.** 파일을 읽고, 픽셀을 보고, 숫자를 다시 잰다.
- 개수를 옮길 땐 **기준 단위와 비율**을 붙인다 — `칸 10 기준 2칸 = 앞치마의 0.17%`.
- 실패 목록은 **종류별로 가른 뒤에** 올린다. 「N종이 죽습니다」는 대개 셋이 섞여 있다:
  진짜 고장 · 두 번 못 돌리는 구조 · **검사 쪽 결함**.
- 도구를 고칠 땐 **같은 파일의 형제 함수**를 같이 본다. 하나만 틀린 경우가 흔하다.
- 도구가 **모르는 것을 모른다고 찍게** 만든다 — 「유닛 0기 — 이번 판에서 확인되지 않았습니다」처럼.
  침묵은 0으로 읽힌다.

### 🔴 우리가 **찍는** 라벨은 더 비싼 근거를 요구한다
09-24에 「희귀함_유닛C은 이 설정으로 못 만든다 — **커밋본을 만든 설정은 남아 있지 않다**」를
`rebuild="금지"` 표식에 박으려다, 박기 직전에 관문을 한 번 돌려 보고 멈췄다.
**바로 옆 파일(`gen_scan_rig`)에 있었다** — 정점·삼각형이 한 개도 안 달랐다.
```
사람이 읽는 주석에 틀린 사실  →  누군가 읽다가 의심한다
기계가 읽는 표식에 틀린 사실  →  **아무도 다시 안 본다**
```
표식은 「확인 끝났다」는 신호라서 틀리면 **탐색을 영구히 닫는다.**
→ **표식을 박기 전에 그 항목을 한 번 돌려 본다.**
→ 관문이 **건너뛴 것을 「통과」로 세지 않게** 한다. 합계에 섞이면 「전부 통과」로 읽힌다.

### 🔴 「전부」라는 말을 세어 본 적이 있나
09-24에 blender가 같은 질문을 자기 도구에 대 봤더니 **두 번 연속 거짓**이었다:
```
「공용 클립에 idle을 입혀 봤다」  →  게임은 idle·walk·attack **셋**을 쓴다.
                                   문턱 넘는 92종 중 **43종이 idle에선 +0.0**이었다 — 절반을 못 봤다
「181개 항목을 전부 돌렸다」      →  실제는 213개. **32항목이 한 번도 관문을 안 지났다**
```
⚠️ 둘 다 **도구가 거짓말한 게 아니라 우리가 도구에 입력을 덜 준 것**이다. 그래서 더 안 보인다.

→ **「전부」의 정의를 손으로 쓰지 말고 유도한다.**
```
① 파일 목록에서 훑어 모은다(사람이 적은 목록을 쓰지 않는다)
② 못 읽는 것이 있으면 **이름을 찍고 실패**한다 — 조용히 건너뛰지 않는다
③ 모은 수와 **실제 대상 수**를 견주고, 다르면 **양쪽에만 있는 이름을 찍는다**
```

### 예측 기준은 **결과 보기 전에만** 고친다
09-24: 「나/가가 0.83이면 아직 뭔가 있다」로 기준을 걸었다가, 결과가 나오기 전에 모형을
다시 따져 「0.80~0.90은 정상」으로 낮췄다. **그건 정당하다.** 결과를 보고 고치면 아니다.
→ 기준을 바꿀 때는 **언제 바꿨는지**를 같이 적는다.

### 「틀린 규칙」과 「이 게임에 안 맞는 규칙」은 다르다
「죽지 않는 것은 자동으로 안 잡는다」는 일반적으로 옳은 규칙인데, 이 게임에선 **반대**였다
(스토리 건물을 미리 깎아두는 것이 설계다). **「일반적으로 옳은가」로는 못 거른다.**
→ 그래서 처방은 규칙을 고치는 게 아니라 **이 게임의 사정을 그 코드 옆에 적는 것**이다.

### 현상을 원인처럼 적으면 다음 사람이 안 판다
같은 건의 전날, 「척추 이름이 원래 두 갈래다 — 아는 상태로 두자」로 닫았고 PM이 승인했다.
하루 뒤 원인이 나왔다: **생성기가 둘이었다**(그 다섯 종이 정확히 다른 생성기 산물).
「두 갈래다」는 **현상**인데 **원인처럼** 적혀서, 「이미 아는 것」으로 보이게 만들었다.
→ 「아는 상태로 두자」를 승인할 땐 **「무엇을 아는가 / 무엇을 모르는가」를 갈라서** 적게 한다.
  모르는 것은 「모른다」로 남아야 누군가 판다.
