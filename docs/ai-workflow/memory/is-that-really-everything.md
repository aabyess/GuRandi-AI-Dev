2026-09-24에 **「전부」라는 말이 하루에 두 번 거짓**이었다. 둘 다 도구가 거짓말한 게 아니라
**사람이 도구에 입력을 덜 준 것**이다. 도구는 받은 만큼만 맞게 말했다.

```
「움직일 때 멀쩡한지 봤다」  → 공용 클립 셋(idle·walk·attack) 중 **idle 하나**만 먹였다
「항목 181개를 전부 돌렸다」 → 유닛 생성기 열 중 **다섯**만 돌았다. 213개 중 181개
```
- 하필 **안 본 쪽이 문제가 나는 쪽**이었다. 팔이 몸을 가로지르는 건 걷기·공격에서 나고,
  idle은 팔을 옆에 내려 가장 안 터지는 클립이다. **가장 안전한 하나로 전부를 판정하고 있었다.**
- 얼마나 놓쳤는지 **세어서** 말할 것. 「절반쯤 놓쳤을 것이다」는 잊히고 **「92종 중 43종을 놓쳤다」**는 안 잊힌다.
- ⚠️ 그렇다고 **일반화하지 말 것**: 같은 날 `clip_spread`를 셋으로 다시 돌리니 결론이 안 바뀌었다
  (세 클립 차 최대 +0.43, 기준 3.0). **자마다 다르다 — 그래서 자마다 돌려 봐야 안다.**

## 목록은 손으로 쓰지 말고 **유도**할 것 (PM 지시)

머리말에 「새로 만들면 여기 추가할 것」을 적는 건 **사람이 기억해야 하는 자리를 만드는 것**이고,
바로 그래서 32개가 빠졌다. `check_entries.py`를 이렇게 고쳤다:
```
① 파일 목록에서 훑는다(gen_*.py + fix_unit_fbx.py, 본문에 "Art/Units"가 있으면 유닛 생성기)
② 유닛 생성기인데 항목 표를 못 찾으면 **이름을 찍고 실패**한다(조용히 안 건너뛴다)
③ 모은 항목 ↔ Assets의 실제 파일을 견주어 **양쪽에만 있는 이름을 찍는다**
```
③을 켜자마자 내가 **머릿속으로 맞춘 산수**가 틀렸다고 나왔다 — 「212개니 213이 맞다」는
**항목 수(중복 포함) 213**과 **이름 수 204**를 헷갈린 것이었고, 설정이 아예 없는 유닛이 **여덟**이었다.
👉 **사람이 맞춘 수는 근거가 아니다. 기계가 맞추게 할 것.**

## 판정을 **문자열 목록**에 걸지 말 것

옛 관문은 출력에서 예외 **이름**을 정규식으로 찾았다. 그 목록에 `CalledProcessError`가 없어서
**초월_유닛E_AD가 죽었는데 OK로 찍혔다.** 예외 이름 목록도 사람이 관리하는 자리라 또 빠진다.
→ **「돌았다」가 아니라 「그 파일이 나왔다」로 판정한다**(돌리기 전에 지우고, 끝난 뒤 있는지 본다).

## 넘겨짚은 경로도 같은 병

③을 처음엔 `Assets/Art/Units/<이름>/<이름>.fbx`로 넘겨짚었더니 `안흔함_유닛D`
(실제로는 `Art/Characters/*.glb`)가 **없는 결함**으로 잡혔다. 항목이 `path=`를 선언하면 그걸 볼 것.
