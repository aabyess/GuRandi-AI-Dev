**어떤 값이 원인 같아 보이면, 계산을 검토하기 전에 「그 값이 화면에 실제로 쓰이는가」를 먼저 확인한다.**

**Why:** 2026-09-24 하루에 **같은 병이 셋** 나왔고 셋 다 몇 시간씩 먹었다.

### 🔴 다음 단계 — **값은 쓰이는데 두 군데를 정한다**
09-24 저녁에 나온 결함 둘이 같은 얼굴이었다:
```
포탈: 지름 27.09가 **높이까지** 정했다   (캡슐 규칙 때문에)
전투: 스캔 주기 0.25초가 **교체 판정까지** 조였다 (같은 nextScanTime을 두 경로가 씀)
```
둘 다 **각자의 자리에서는 옳은 값**이다 — 지름 27.09는 포탈 크기로 맞고, 0.25초는 전체 훑기
주기로 맞다. **높이를 정하라고 준 값이 아니고, 교체 판정을 조이라고 준 값이 아닐 뿐이다.**

→ 그래서 찾는 법이 다르다. **「이상한 값 찾기」가 아니라 「이 값이 몇 군데를 정하나 세기」다.**
   한 상수가 두 가지를 정하고 있으면 **그중 하나는 아무도 의도한 적이 없다.**

### 🔴 엔진 판 — 엔진에 숨은 규칙이 우리 숫자를 덮어쓴다
포탈을 「높이 1짜리 얇은 원판」으로 만들려고 `localScale = (지름, 0.5, 지름)`을 줬다.
그런데 원기둥 프리미티브는 **CapsuleCollider**를 달고 오고, **유니티 캡슐은 높이가
2×반지름보다 작아질 수 없다.** 그래서 y배율은 무시되고 **반지름짜리 구**가 됐다 —
즉 **포탈 지름이 트리거 높이를 정하고 있었다.**
```
유닛랜덤  지름배율 37.50 → 트리거 꼭대기 27.0  vs 위습 아래끝 25.5  → 1.5 겹침 → 된다
흔함선택  지름배율 27.09 → 트리거 꼭대기 21.8  vs 위습 아래끝 25.5  → 3.7 모자람 → 안 된다
```
**되는 쪽도 1.5 차이로 겨우 되고 있었다.** 위습이나 포탈 크기를 조금만 바꾸면 조용히 죽는다.
→ **우리가 쓴 값이 그대로 쓰인다고 믿으면 안 된다.** 엔진이 조용히 고쳐 쓰는 값이 있다.

⚠️ 단위도 같은 병의 얼굴이다. `NavMeshAgent.radius`는 **로컬값**이고 트랜스폼 배율을 탄다 —
위습 로컬 0.0056이 배율 50을 타서 월드 0.28이다. 그걸 굽기 반지름 0.5 옆에 나란히 찍으면
「1/50이다」라는 틀린 결론이 나온다. **기준이 다른 두 숫자를 나란히 두지 않는다.**

### 🔴 가장 어려운 판: **내가 쓴 코드**
```
남의 코드가 안 쓰이는 건 읽으면 보인다.
내 코드가 안 쓰이는 건 **기억이 「내가 넣었다」고 말해 줘서** 안 읽는다.
```
09-24에 내 오판 여섯 중 **셋이 내가 쓴 코드**였다 — 회피 끄기(스포너가 덮음) ·
「지워도 동작 변화 0」(위습은 스포너를 안 거쳐서 **그 줄이 위습에겐 유일하게 살아 있었다**) ·
카메라 시작값(`Start`가 덮음). 셋 다 **읽었으면 30초**인데 기억으로 답했다.
그리고 그 기억을 근거로 **남의 시험을 멈춰 세웠다.** 지시를 기억하는 쪽도 같은 함정이다 —
PM은 사장님 지시를 기억해서 코드를 안 봤다.

**규칙:** 「내가 넣은 거라 안다」는 근거가 아니다. 내 코드일수록 **파일을 연다.**

**How to apply:**
- 값을 고치기 전에 **그 값을 읽는 쪽**을 찾는다. 덮어쓰는 코드(`Start`·런타임 초기화)가 있는지,
  저장되는 값인지, 그 기능 자체가 꺼져 있는지.
- 「고쳤는데 화면이 안 바뀐다」가 나오면 **내 계산을 의심하기 전에 경로를 의심한다.**
- ⚠️ **결과가 나오는 시험은 결과가 틀려도 결과처럼 보인다.** 회피가 꺼진 채로 반지름을 올려
  「안 퍼진다」를 보면 「반지름은 원인이 아니다」라는 **틀린 결론이 숫자와 함께** 나온다.
  시험을 설계할 때 「이 시험이 뜻을 가지려면 무엇이 켜져 있어야 하나」를 먼저 적는다.

### 「만들거나 가져오기」 함수는 가져온 뒤에도 값을 다시 써야 한다
```csharp
var x = AssetDatabase.LoadAssetAtPath<T>(path);
if (x != null) return x;        // ← 처음 만들 때의 값이 영원히 남는다
```
**같은 모양으로 세 번 당했다** — 바닥 재질 `_BaseMap`(f3da5f93) · 크기별 재질 · 위습 발광(cdf34b4c).
고치는 법: 있으면 값을 다시 써 넣고 `SaveAssetIfDirty`까지 부른다.
⚠️ **성공 메시지는 성공의 근거가 아니다.** 「맞췄습니다」를 찍은 뒤에 파일을 열어 봐야 안다.

### 곁가지: 「몇 칸」은 칸 크기 없이 옮기지 않는다
같은 NavMesh를 두고 「구멍 14칸」과 「구멍 2칸」이 나왔다. 갈린 것은 결함이 아니라 **해상도**다
(60칸으로 좁은 띠를 보면 벽 칸 비중이 커진다). 개수를 옮길 때는 **기준 단위와 비율**을 붙인다 —
`칸 10 기준 2칸 = 앞치마의 0.17%`. 도구 보고문도 그렇게 찍게 해 뒀다(`ApronProbe`).
