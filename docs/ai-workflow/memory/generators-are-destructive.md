`Tools/generate_unit_stats.py` / `generate_recipe_assets.py`는 **읽기 도구가 아니라 쓰기
도구**다. `Assets/Data/Units/Roster`에 파일을 쓰고, 기존 유닛의 스탯을 0으로 덮고
`.meta` GUID를 재발급한다. GUID가 바뀌면 씬·조합식 참조가 전부 끊긴다.

**Why:** 2026-09-02에 구현담당3이 드라이런을 검증하려고 스크래치 폴더를 실제 로스터에
심볼릭 링크로 걸었다가 **190개가 덮이고 `기본_*` 임시 유닛 232개가 생성**됐다.
전량 복구했고 커밋에는 안 남았다. 원인은 "읽기만 할 줄 알았다"는 판단 착오다.

**How to apply:** 생성기를 검증할 때 실제 경로를 링크로 걸지 말고, **함수만 따로 시험**하거나
출력 경로가 확실히 스크래치인지 확인한 뒤 돌린다. 그리고 생성기에 새 재료를 등록할 때
**결과 유닛으로는 등록하지 말 것** — 다른 생성기가 만든 에셋을 덮어쓴다. 참조만 잇고
GUID는 디스크의 `.meta`에서 읽게 한다.

PM 쪽 교훈: 파괴적인 도구를 쓰는 작업을 지시할 때는 **검증 방법까지 같이 지정**한다.
이번엔 "토큰 채우세요"만 주고 어떻게 확인할지는 안 줬다. [[pm-operating-rules]]
